---
name: O.A.S.I.S. presentation principles
description: User requirements for the public-facing O.A.S.I.S. project site.
---

Do not frame O.A.S.I.S. as a student project. Keep the interactive telemetry dashboard on its own page, separate from the presentation landing page. Use readable text and avoid redundant content, generic generated-looking imagery, gratuitous glow/floaters, and orange callout boxes.

For the dashboard, foreground one selected plant at a time. Never reuse another plant's measurements when a plant has no recorded run. Give the three primary readings (air temperature, substrate moisture, and VPD) distinct readable signal colors, values, and profile ranges; use restrained signal accents rather than cheap-looking colored fills. Keep other readings secondary. Keep model results, controller proposals, deterministic replay outcomes, human approval, and hardware execution clearly distinct and truthful. Avoid a large enclosing card with many nested boxes and keep dashboard text at readable sizes.

**Why:** the user asked for a readable, low-clutter dashboard with plant-by-plant separation and clear signal identities.

**How to apply:** preserve the landing-page/dashboard separation and the restrained technical presentation when extending this project; keep unavailable plant data unavailable and label notebook playback as replay.
